0Что мы вообще делали

В лабе 3 была программа «Ресивер» — считает массу газа. В лабе 4 мы её улучшили: добавили выбор газа, удобные поля для чисел, красивый вывод, второе окошко и защиту от ошибок.

Зачем всё это? Чтобы программой было удобно пользоваться и чтобы она не падала, что бы пользователь ни ввёл. Всё остальное — инструменты для этого.

1RadioButton и Panel

Что такое RadioButton

Обычная кнопка-кружок. Нажимаешь — внутри появляется точка. Нажимаешь другую кнопку в той же компании — первая сама гаснет.

RadioButton

Как вопрос «пол: мужской / женский» — выбрать можно только один. Нажал «женский» — «мужской» сам выключился.

CheckBox (для сравнения)

Как «отметьте, чем болели» — можно наставить сколько угодно галочек.

У нас выбирается один газ из трёх — значит, RadioButton.

Как программа понимает, какая нажата

У каждой кнопки есть свойство Checked — «включена или нет» (true / false).

csharpif (radButtonAir.Checked)  return 287;  // воздух
if (radButtonAzot.Checked) return 297;  // азот
if (radButtonCO2.Checked)  return 189;  // углекислый газ

Зачем Panel — «коробка для кнопок»

Представь, что на форме две группы кнопок: «газ» (3 кнопки) и «тип ресивера» (2 кнопки). Если все они лежат просто на форме — программа запутается:

✗

Без Panel: выбрал газ «воздух» — и тип ресивера сам выключился, хотя это про другое. Программа считает, что все радиокнопки на форме — одна компания, и включён может быть только один.

Решение — Panel. Это белая коробка на форме. Всё, что внутри одной коробки — «одна компания». Внутри — включён только один. Разные коробки друг на друга не влияют.

✓

У нас: одна Panel с тремя кнопками газа. Просто и аккуратно. Если завтра понадобится вторая группа — её кладут в отдельную панель.

Фраза для сдачи

💬

«Panel — это коробка для радиокнопок. Внутри коробки включён только один. Разные коробки не влияют друг на друга. У меня три кнопки газа — в одной коробке, потому что это один вопрос».

2NumericUpDown — умное поле для чисел

Поле с числом и двумя стрелочками вверх-вниз. Кликаешь стрелку — число меняется. Можно ввести с клавиатуры.

text[   10,5   ][▲][▼]

Чем лучше обычного текстового поля

В лабе 3 мы брали обычное поле и писали кучу кода, чтобы туда нельзя было ввести букву. В лабе 4 мы это выкинули — NumericUpDown сам не даёт ввести буквы. И сам держит число в границах:

СвойствоЧто делает
Minimum / Maximumнижняя и верхняя граница (например, давление от −1 до 10000)
DecimalPlacesсколько знаков после запятой разрешено
Incrementна сколько меняется при клике по стрелке
Valueтекущее значение
✓

Кучу кода из лабы 3 удалили — контрол делает всё сам. Это и есть смысл готовых компонентов: не писать то, что уже написано.

Одна хитрость — тип decimal

У NumericUpDown значение хранится в типе decimal (точный тип для денег и чисел). А наша формула работает с double (обычный тип для вычислений). C# не даёт их перепутать — нужно явно превратить одно в другое:

csharpdouble p = (double)Pressure.Value;   // ← скобки (double) обязательны
⚠

Спросят «Зачем (double)?» — «Value — тип decimal, а формула на double. Нужно явное превращение».

3Свой класс FormOutStr

Проблема

Программа посчитала массу: 10,7977123456... — длиннющее число. Показывать такое некрасиво. Хочется: 10,7977 (4 знака).

Простое решение

csharpMassa.Text = m.ToString("F4") + " кг";

Это правильно. Но в лабе требуют отдельный класс — и вот зачем.

Смысл класса на пальцах

Представь, что у тебя десять программ, и везде надо красиво выводить числа. Писать одно и то же в десяти местах — глупо. А если завтра надо поменять «4 знака» на «6 знаков» — править в десяти местах.

Решение: один раз написать «коробочку с кнопкой». Снаружи — одна кнопка «сделай красиво», внутри — вся логика. Это называется инкапсуляция — «сложное спрятать в коробку, снаружи дать простое».

Коробка — класс FormOutStr. Кнопка на коробке — метод ToStr:

csharppublic class FormOutStr
{
    public string ToStr(string s, int n)   // s — число строкой, n — сколько знаков оставить
    {
        // превратить строку в число, округлить, вернуть обратно строкой
    }
}

Использование:

csharpFormOutStr formatter = new FormOutStr();   // сделали коробку
Massa.Text = formatter.ToStr(raw, 4);      // нажали кнопку «сделай красиво»

Почему у нас лучше, чем в методичке

В методичке метод такой:

csharpstr = s.Remove(i + n + 1);   // отрезать всё после n знаков
✗

Если в строке меньше символов, чем надо отрезать — программа падает с ошибкой. Например, число 5 (строка «5», запятой нет) — и всё ломается.

✓

У нас метод защищён: сначала проверяем «это точно число?», потом красиво округляем. Это плюс на защите — «я исправил ошибку из методички».

4Вторая форма и «модальность»

Что такое «вторая форма»

Программа — это не обязательно одно окно. Может быть главное окно и куча дополнительных: настройки, «о программе», «сохранить файл». Каждое окно — свой класс.

У нас: Form1 — главное окно (расчёт), Form2 — маленькое окошко для ввода объёма.

Как открыть второе окно — два способа

СпособНазваниеЧто происходит
form2.Show()Немодальноеокно открылось, но главное тоже работает — можно кликать и там, и там
form2.ShowDialog()Модальноепока не закроешь маленькое окно — главное заморожено
Модальное — касса

Как касса в магазине. Пока не расплатишься — дальше не пройдёшь.

Немодальное — вкладка

Как вкладка в браузере. Открыл — а другие вкладки работают.

Когда что:

  • Диалог ввода («введите объём») → модальное. Пользователь сначала отвечает, потом программа идёт дальше.
  • Справка, «о программе» → немодальное. Пусть висит сбоку, не мешает.

У нас модальное — потому что надо дождаться объёма от пользователя, прежде чем считать.

Как понять — нажали ОК или Отмена

После закрытия модального окна главному надо узнать: принять ответ или отменить?

Для этого у каждой кнопки есть свойство DialogResult:

  • DialogResult = OK — пользователь согласился;
  • DialogResult = Cancel — отказался.

Пользователь кликнул такую кнопку → окно само закрылось → главное окно спрашивает:

csharpif (formVolume.ShowDialog(this) != DialogResult.OK)
    return;   // нажали «Отмена» — ничего не меняем

Читается так: «открыл окошко, дождался закрытия. Если закрыли не через OK — выхожу, объём не трогаю».

Зачем public у поля Volume

Form1 хочет прочитать, что пользователь ввёл в поле Volume в Form2. Но по умолчанию поле спрятано от других классов — private, снаружи не видно. Мы явно разрешаем показывать его:

csharppublic TextBox Volume;   // в Form2.Designer.cs

Теперь Form1 может написать:

csharpdouble newV = Convert.ToDouble(formVolume.Volume.Text);
⚠

Спросят «Почему public?» — «По заданию лабы нужно читать поле из главной формы; чтобы было видно снаружи — делаем public».

5try / catch — «попробуй / поймай»

Проблема

В программе есть места, где может случиться «бум»:

  • деление на ноль;
  • пользователь ввёл букву вместо числа — превращение в число падает;
  • вылезли за границу массива.

Если это не поймать — программа закроется с ошибкой. Преподаватель такое не любит.

Решение — «попробуй / поймай»

csharptry
{
    // тут код, который МОЖЕТ упасть
    double m = (p + 1) * 98000 * V / (R * (T + 273));
}
catch (DivideByZeroException)
{
    // сюда попадаем ТОЛЬКО если было деление на ноль
    MessageBox.Show("Температура не может быть равна −273 °C");
}

Как это работает

  1. Программа заходит в блок try и выполняет код.
  2. Всё ок — блок catch пропускается, работа идёт дальше.
  3. Что-то упало внутри try — программа не закрывается, а ищет подходящий catch.
  4. Нашла — выполнила, что там написано, и работает дальше.
  5. Не нашла — увы, падает как обычно.

Почему у нас два catch

В try у нас весь расчёт. Там может упасть:

  • деление на ноль — если температура ровно −273;
  • что-то ещё — например, ошибка превращения строки в число.

Поэтому сначала ловим конкретно деление на ноль (у него своё понятное сообщение), потом — всё остальное:

csharptry { ... }
catch (DivideByZeroException ex) { /* конкретно про ноль */ }
catch (Exception ex)             { /* всё остальное */ }
!

Важно: порядок! Exception — это «родитель» всех ошибок. Если поставить его первым — он перехватит всё, и до второго catch дело не дойдёт. Правило простое: сначала конкретное, потом общее.

⚠

Спросят «Почему два catch?» — «Для деления на ноль хочу отдельное понятное сообщение, для остальных — общее. Сначала ловлю конкретную ошибку, потом общую. Exception — родитель всех, поэтому идёт последним».

6Отладка — F9, F10, F11

Точка останова (breakpoint) — «стоп-кран»

Представь: программа выдаёт неправильный результат. Где ошибка? В каком месте? Глазами не видно. Тогда ставим «стоп-кран».

  • Кликаешь слева от строки кода или нажимаешь F9 — появляется красный кружок.
  • Запускаешь программу F5 — она останавливается ровно на этой строке. Дальше не идёт, пока не разрешишь.

Зачем это нужно

Пока программа «стоит» на точке, можно:

  • Навести мышь на любую переменную — появится подсказка с её значением. Сразу видно: p = 10, T = 0, R = 287 — всё ли как ожидалось?
  • Идти дальше по одной строке.

Шагать по строкам

КлавишаЧто делает
F10выполнить одну строку. Если эта строка вызывает функцию — функция выполнится целиком, как «чёрный ящик», и перейдём к следующей
F11выполнить строку, но если это вызов функции — зайти внутрь и идти по ней построчно
F5«продолжить»: бежать до следующей точки останова или до конца
Shift+F5остановить отладку
F10 — с обходом

Идёшь по тексту программы построчно, в чужие комнаты не заходишь.

F11 — с заходом

Если строка говорит «зайди в комнату», заходишь внутрь и идёшь там.

Когда нужен F11, если F10 быстрее: когда подозреваешь, что внутри функции что-то не так. Например, результат неправильный, а строка m = Calculate(...) выглядит подозрительно — заходишь в Calculate и смотришь, что там творится.

7Как всё работает вместе

  1. Открыл программу — уже выбрана «Воздух» (Checked = true). Значит, R = 287.
  2. Пользователь вводит давление и температуру через NumericUpDown. Буквы ввести нельзя — контрол сам не даёт. За границы выйти тоже нельзя.
  3. Нажал «Изменить объём» → ShowDialog() открыл Form2 модально. Пока окно открыто, главное окно заморожено.
  4. Ввёл 2, нажал OK. Form2 закрылась, вернула DialogResult.OK. Главное окно прочитало Volume.Text, превратило в число, сохранило в V = 2.
  5. Нажал «Вычислить массу». Программа:
    • прочитала p и T из полей;
    • посмотрела, какая радиокнопка включена, взяла нужный R;
    • посчитала m;
    • через FormOutStr сделала красиво — 4 знака после запятой;
    • показала в Massa.Text.
  6. Если внутри try что-то упало — программа не закрылась, а показала понятное сообщение через MessageBox.

8Вопросы на защите — короткие ответы

Кликни на вопрос — раскроется ответ. Прогони все перед сдачей.

Чем RadioButton отличается от CheckBox?

CheckBox — можно наставить сколько угодно галочек. RadioButton — в одной компании только один включён. У нас газ — один, поэтому RadioButton.

Зачем Panel?

Это коробка для радиокнопок. Внутри коробки включён только один, а разные коробки друг на друга не влияют. У меня три кнопки газа — в одной коробке, потому что это один вопрос.

Зачем (double) перед Pressure.Value?

Value — тип decimal, а формула на double. Нужно явно превратить одно в другое.

Зачем класс FormOutStr, если есть ToString("F4")?

Чтобы один раз написать форматирование и использовать везде (переиспользование). Плюс это требование лабы — вынести в отдельный класс.

Что такое модальное окно?

Окно, которое блокирует главное, пока не закроется. Открывается через ShowDialog(). Немодальное — через Show(), оно не блокирует.

Как узнать, нажали ОК или Отмена в дочерней форме?

По DialogResult. У кнопки ОК стоит DialogResult = OK. После ShowDialog() проверяю if (form.DialogResult == DialogResult.OK).

Почему поле Volume в Form2 — public?

Потому что его читает Form1 снаружи. По умолчанию поля private, снаружи не видны, поэтому явно сделали public.

Зачем try / catch?

Чтобы при ошибке (деление на ноль, неверный формат) программа не падала, а показала понятное сообщение и продолжила работу.

Почему два catch и почему деление на ноль первым?

Exception — родитель всех ошибок, перехватит всё. Ставлю его последним, чтобы специфичные ошибки ловились своим обработчиком. От конкретного — к общему.

Что такое точка останова?

Красный кружок на строке (F9). Программа останавливается на ней при запуске. Можно навести на переменные и увидеть их значения.

Чем F10 отличается от F11?

F10 — следующая строка, функция выполняется целиком как чёрный ящик. F11 — тоже шаг, но если это вызов функции — зайти внутрь неё.

Что будет, если T = −273?

В формуле будет деление на ноль → DivideByZeroException → catch покажет MessageBox, программа продолжит работать.

Где хранится объём V?

В поле private double V в классе Form1. Меняется через кнопку «Изменить объём», читается при расчёте массы.
